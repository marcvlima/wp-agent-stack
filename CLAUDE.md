# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

`wp-agent-stack` is a **library repo, not a runnable application**. It's a reusable
collection of agentic-development assets for WordPress projects — skills, agents,
instructions, hooks, and MCP configs. There is no build/lint/test tooling of its own;
assets are validated in the *origin* project (a real WordPress site) before being
promoted here.

It is packaged as a real **[APM (Agent Package Manager)](https://github.com/microsoft/apm)**
package (`apm.yml` at the root) — the actual open-source Microsoft tool, not a
custom/invented format. `apm` (CLI) is expected to be available on this machine; if not,
`curl -sSL https://aka.ms/apm-unix | sh`. Don't build a custom installer or converter —
`apm compile`/`apm install`/`apm pack` already do full cross-assistant deployment
(Claude Code, Cursor, GitHub Copilot, Windsurf, and Antigravity via explicit `--target`).

Everything in this repo must be **project-agnostic**: no site-specific names, paths, or
business logic. If you're asked to add something that still references a specific
project, generalize it first.

## Structure

```
wp-agent-stack/
├── apm.yml                — package manifest: name, version, targets, dependencies
├── apm.lock.yaml           — lockfile (commit it, like a package-lock.json)
├── .claude-plugin/         — plugin.json synthesized from apm.yml (Claude Code direct-install)
├── .github/plugin/         — plugin.json synthesized from apm.yml (Copilot ecosystem)
└── .apm/                   — SOURCE TREE — every primitive is authored here, nowhere else
    ├── skills/<name>/SKILL.md (+ scripts/, references/, assets/, examples/)
    ├── agents/<name>.agent.md
    ├── instructions/<name>.instructions.md
    ├── prompts/<name>.prompt.md
    └── hooks/<name>.json
```

**Critical constraint (verified against the real `apm` CLI, not assumed):** only
`.apm/<type>/` is discovered by `apm pack`/`apm install`. Top-level folders like
`skills/` or `agents/` at the repo root are **not** picked up — content placed there
silently never ships. Also: primitive folders get bundled as-is by directory (e.g.
`.apm/agents/` copies whatever files sit inside, unfiltered) — never drop a stray
README or non-conforming file inside a `.apm/<type>/` folder, since it will be packed
and deployed to consumers as if it were real primitive content. Put explanatory docs in
this file or the root README instead.

`.claude-plugin/plugin.json` and `.github/plugin/plugin.json` are generated by
`apm pack` from `apm.yml` — regenerate with `apm pack` after editing `apm.yml` and
commit the result (small, derived, enables direct plugin install without a manual pack
step). `build/` and `apm_modules/` are pack/install output, gitignored — never commit.

## Working in this repo

- **Promotion workflow**: validate the pattern in production in a real project first,
  generalize it (strip project-specific details), add it under `.apm/<type>/` following
  that primitive's exact naming convention (see
  [author-primitives docs](https://microsoft.github.io/apm/producer/author-primitives/)),
  bump `version` in `apm.yml` (semver — MINOR for a new primitive, PATCH for tweaks,
  MAJOR for breaking changes), document it in the primitives table in the root
  `README.md`, then validate before committing:
  ```bash
  apm compile --validate
  apm pack --dry-run --verbose   # confirms exactly which files would ship
  ```
  `includes: auto` in `apm.yml` means new files under `.apm/` are picked up
  automatically — no manifest edit needed to *include* them, only to bump the version.
- **Skills** follow the format in
  [.apm/skills/woocommerce-custom-product-filter/SKILL.md](.apm/skills/woocommerce-custom-product-filter/SKILL.md):
  YAML frontmatter with `name` (must match the parent directory name) + a `description`
  written as an activation contract ("Activate when…" / "Use SEMPRE que…"), then the
  guide body, then a `references/` folder with the actual code/config referenced by the
  guide. Write skill bodies in Portuguese, matching the existing skill.
- No package manager, build step, or test suite exists for the WordPress-side content —
  verifying a skill's guidance means validating it against a real WordPress/WooCommerce
  install, not against anything in this repo. Verifying the *packaging* means running
  the `apm` commands above.

## Consuming these assets in a project

```bash
apm install marcvlima/wp-agent-stack --target claude,cursor,copilot,windsurf
apm install marcvlima/wp-agent-stack --target antigravity   # explicit-only, not in defaults
```

See the root [README.md](README.md) for the full explanation of what gets deployed
where.
