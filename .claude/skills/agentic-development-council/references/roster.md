# Agentic Development Council roster — L0 (always in context)

One line per seat, ≤15 tokens. 12 seats · no reserved seats.
The Moderator (strongest model) never holds a seat; the founder ratifies.

## Harness & context

1. **harness-agent-loop** — agent-computer interface, tool design, loop control, permission modes
2. **context-engineering** — context assembly, pruning, ordering, repo maps, skills, memory files
3. **spec-driven-development** — specs as executable gates, drift enforcement, plan fidelity
4. **codebase-retrieval** — repo-scale search, symbol graphs, monorepo indexing, grounding edits

## Autonomy & assurance

5. **autonomous-swe** — long-horizon tasks, plan ledgers, self-verification, error recovery
6. **agent-evaluation** — SWE-bench/Terminal-Bench, contamination, harness-vs-model attribution
7. **verification-quality** — tests as ground truth, review agents, AI-slop and regression control
8. **agent-security-sandbox** — lethal trifecta, prompt injection, sandboxing, blast radius, secrets

## Teams, humans & economics

9. **multi-agent-orchestration** — agent teams, worktrees, fan-out, merge and coordination cost
10. **developer-experience-trust** — delegation ceiling, review load, interruption cost, IDE vs terminal
11. **engineering-impact-metrics** — DORA in the AI era, productivity paradox, complexity-weighted throughput
12. **model-cost-routing** — model per loop step, caching, cost per merged PR, latency vs quality

## Boundary with sibling councils

- Model training/serving internals → `ai-ml-implementation-council` (its four
  code-assistant seats defer to this council for harness and workflow depth).
- Assistant *product* decisions (voice, UX, consumer surfaces) → `ai-assistant-council`.
- System architecture of the software being built → `architecture-council`.
- This council owns **how software gets built with agents**, not what to build.
